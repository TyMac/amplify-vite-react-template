- Remaining vulnerable paths are bundled under Amplify Gen 2 backend packages such as `@aws-amplify/data-construct` and `@aws-amplify/graphql-api-construct`, including nested AWS SDK copies.
- Advisory examples: `GHSA-m7jm-9gc2-mpf2`, `GHSA-jmr7-xgp7-cmfj`, `GHSA-8gc5-j5rx-235r`, `GHSA-gh4j-gqv2-49f6`.
- Minimal safe remediation attempted/considered: avoid force/major/downgrade paths; prefer upstream Amplify/AWS SDK dependency refresh. A global override would mix major `fast-xml-parser` lines across bundled AWS SDK/Amplify internals and was not applied because that is riskier than the toolchain-only residual exposure.
- Reachability: primarily dev/build/deploy tooling and AWS SDK XML parsing paths, not Barista public user-input processing in the web app. Residual risk is kept visible in audit output.
- Follow-up trigger: revisit when `@aws-amplify/backend`, `@aws-amplify/backend-cli`, or AWS SDK releases include patched nested `fast-xml-parser`/`fast-xml-builder` versions without requiring unsafe force upgrades.
